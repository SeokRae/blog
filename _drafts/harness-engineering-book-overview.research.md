## 근거 D — Part 간 논리적 연결고리 (요청 3)

각 연결은 책이 **명시적으로** 밝힌 것만 채택했다.

**1부 → 2부.** 1부는 "왜"를 진단하고 처방(5축: 권한·도구·검증·상태·관측)까지만 제시하고 구현은 미룬다. 1장 본문이 직접 예고: "이 다섯 축이 실제로 어떻게 구성되는지는 2부에서 따로 다룹니다"(`chapter_01:161`). 3장 도입은 이를 받아 "앞부분(1·2장)에서 '왜 하네스인가'를 이해했다면, 이제 질문은 '어떻게 구성하는가'로 옮겨갑니다"(`chapter_03:36`).

**2장 → 3장 (Part 내부의 다리).** 2장에서 만든 파일 5개를 3장이 그대로 해부한다. "이 장은 그 다섯 파일을 세 덩어리로 나눠 봅니다"(`chapter_03:34`). 즉 실습이 먼저, 개념화가 나중 — 의도적 순서.

**3장 → 4·5·6장.** 3장이 경계선만 긋고 각 기둥을 한 장씩 심화. "3장은 2부의 지도입니다"(`chapter_03:36`). 실제로 4장은 '## 팀 통신 프로토콜' 섹션을 비워둔 채 넘기고(`chapter_06:226`), 6장이 그 섹션을 채우면서 회수한다.

**2부 → 3부 (가장 중요한 연결).** 3부의 존재 이유는 **반복**이다. 7장 도입이 서사로 설명: 코드 리뷰 팀 → 풀스택 팀 → 마이그레이션 팀, "여섯 번째 팀을 만들던 날, 엔지니어는 에디터 화면에서 똑같은 작업 패턴이 반복되고 있음을 깨닫습니다"(`chapter_07:36`). 그리고 2부에서 배운 원칙("반복되는 절차가 스킬의 재료")을 2부 자신에게 적용한다 — "2부에서 본 여섯 단계 자체가 스킬이 되지 못할 이유가 없습니다"(`chapter_07:45`). **결정적 증거: "2부 전체가 메타스킬의 references/에 모듈로 접혀 있는 셈입니다"**(`chapter_07:109`).

**3부 내부 순서 (7·8 = 설계 / 9·10 = 운영).** 저자가 직접 갈라 놓음: "앞 두 장은 설계의 골격으로… 뒤 두 장은 운영의 골격으로"(`00_front_matter.md:159`). 8장은 "무슨 모양", 9장은 "그 모양을 어떻게 돌릴까"로 이어진다 — "8장이 팀의 모양을 결정했다면, 이 장은 그 팀을 어떻게 작동시킬지를 결정합니다"(`chapter_09:7`). 10장은 마지막 관문: 등록하지 않으면 첫 세션 이후 호출되지 않으므로 앞의 모든 설계가 무효화된다(`chapter_10:44-53`).

| 감독자(동적 분배) | 13장 레거시 마이그레이션 |
| 생성-검증 + 팬아웃 | 14장 디버깅·RCA |
| 스케일별 혼합 | 맺음말 1인→팀→조직 |

저자 표현: **"8장은 패턴의 '지도'를 살펴봤습니다. 실제 '지형'은 4부에서 보여줍니다."**(`chapter_08:421`)

**4부 내부 배치.** 4개 도메인은 난이도·규모 순이 아니라 **패턴 커버리지** 순이다. 11장(가장 익숙한 문제 = 팬아웃) → 12장(경계면 = 복합 패턴 4개) → 13장(규모 = 감독자) → 14장(사후 대응 = 결정론 게이트). 그리고 11장과 14장은 **순환 피드백**으로 닫힌다: "디버깅 팀이 찾은 근본 원인 패턴이 새로운 코드 리뷰 규칙을 만들어 내고, 코드 리뷰에서 놓친 케이스가 디버깅 팀의 입력이 됩니다"(`chapter_14:342`).

**4부 → 5부(부록).** 부록 B가 4부 전체를 횡단해 회수한다: "코드 리뷰 팀과 풀스택 팀, 레거시 마이그레이션과 RCA 팀은 서로 다른 도메인을 다루지만 **실패 모드는 놀랍도록 비슷합니다**"(`appendix_b:7`). 부록 D는 1장이 던진 "왜 산업이 같은 구조에 도달했는가"를 Stripe/클로드 코드 계층 비교로 답한다.

**전체를 닫는 고리.** 1장 파울러의 "안쪽은 확률론, 가장자리는 결정론"(`chapter_01:128`)이 부록 D 원리 5에서 워크플로 8단계 교대표로 구체화된다(`appendix_d:218-227`). 즉 1장 = 명제, 부록 D = 구현. 책이 수미상관 구조.

## 인사이트 후보

블로그가 "인사이트 중심"이므로, 요약이 아니라 **판단**이 될 만한 것들만 추렸다. 각 항목은 근거와 함께 제시했고, 마지막 두 개는 writer/사용자의 경험이 필요하다.

1. **이 책의 진짜 구조는 4부가 아니라 "명제 → 분해 → 접기 → 펼치기"의 4박자다.**
   1부가 명제("모델이 아니라 하네스")를 세우고, 2부가 그 명제를 3개 파일 종류로 분해하고, 3부가 그 분해 절차 자체를 메타스킬로 **접고**, 4부가 접힌 것을 4개 도메인으로 다시 **펼친다**. 결정적 근거는 `chapter_07:109`의 "2부 전체가 메타스킬의 references/에 모듈로 접혀 있는 셈입니다" — 이건 비유가 아니라 파일 구조의 사실 진술이다(SKILL.md 443라인 + references 1,706라인). 목차만 보면 안 보이는 구조.

2. **책이 자기 방법론으로 자기를 만들었다는 사실이 가장 강한 논증이다.**
